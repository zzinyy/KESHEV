# 마지막 총공세 · 1~7일차 실행·제출 안내

화면 틀: 관제 대시보드형. 실행 형태: 포장 없이 프로젝트 폴더에서 실행. 기존 13~22단계 코드와 기록을 보존했습니다. 포장·업데이트 명령은 실행하지 않았으며 포장 스크립트도 추가하지 않았습니다.

## 바로 실행

1. on-client 폴더에서 PowerShell을 엽니다.
2. `node --version`으로 Node 설치를 확인합니다. 제공 기준은 24.19.0, 이번 확인은 24.21.0입니다.
3. `node student/daily-server.mjs`를 실행합니다. 외부 npm 설치가 필요하지 않습니다.
4. `http://127.0.0.1:5195/daily`를 브라우저로 엽니다.
5. ‘다시 조회’를 직접 누릅니다. 첫 조회는 자동으로 하지 않습니다.
6. 기존 기능은 ‘기존 보안 Agent 열기’에서 확인합니다. 기본 제공 서버는 별도 인증 설정을 넣지 않은 연결 없음 상태이며 실제 SDP·AI·집행 연결을 새로 승인하지 않습니다.
7. 종료는 실행한 PowerShell에서 Ctrl+C, 재실행은 같은 명령입니다. 포트 사용 중이면 자신의 기존 실행 창을 확인하거나 `$env:ON_PORT='5196'`으로 빈 포트를 고르고 주소도 함께 바꿉니다.

간편 실행은 이 폴더의 START_DAILY.cmd를 사용합니다. 관리자 실행은 필요하지 않습니다. 기존 Workbench의 프로젝트와 이미 제출한 커밋은 삭제·이동·덮어쓰기하지 않습니다.

| 3 | Windows System·Application 경고·오류 집계 | 최근 24시간 Level 1/2/3, 로그별 최대 5000건. 제한 도달을 표시. 침해·공격 탐지 아님 |

## 제공 코드와 추가 코드

제공 public/app.js·src/server.mjs·기존 학생 함수는 유지했습니다. 기존 학생 대시보드가 있음을 확인했지만 PC 자원 측정은 없으므로 중복 구현하지 않았습니다. 새 파일은 student/pc-readings.mjs(읽기 측정), student/daily-server.mjs(학생 경로와 기존 서버 연결), student/daily.html(PC 관제 화면)입니다. 설치 패키지 반영을 가정하지 않는 별도 학생 실행 방식이며, 선택한 ‘포장 없이 실행’ 범위입니다.

서버는 127.0.0.1에만 열고 Host·Origin을 검사합니다. 학생 조회 경로는 GET만 허용하며 설정·인증·조치 요청을 보내지 않습니다. 새 조회가 진행 중이면 버튼을 비활성화하고 서버도 동시 요청을 하나로 합칩니다. 조회 실패·시간 초과에는 이전 값을 현재 카드에 남기지 않습니다. 과거 추이는 이 화면 세션의 기록으로만 분리합니다.

실측값은 서버가 실행되는 PC 기준입니다. 예제 숫자·실측 JSON은 커밋하거나 외부로 전송하지 않습니다. 네트워크 이름·로그 원문·IP·토큰을 문서나 GitHub로 업로드하지 않습니다. 로그는 count만 결과에 포함하며 반환용 오류는 고정된 이유로 제한합니다. 조회 기록은 브라우저 메모리의 최근 20회만 보관하고 화면을 닫으면 사라집니다.

## 막힐 때

| 증상 | 확인·다음 행동 |
|---|---|
| node 명령 없음 | Node 설치 후 새 PowerShell에서 버전 확인 |
| 실행 파일 없음 | on-client 폴더에서 실행하는지 확인 |
| EADDRINUSE | 자신의 서버 창을 확인하거나 빈 ON_PORT 사용. 다른 서버를 강제로 종료하지 않음 |
| 조회 실패·시간 초과 | 서버 실행 상태 확인 후 직접 다시 조회. 예제 값으로 대체하지 않음 |
| 방화벽·로그 확인 불가 | 일반 권한 읽기 제한·정책·서비스 상태를 담당자에게 확인. 관리자 권한·설정 변경으로 우회하지 않음 |
| SDP 미연결 | PC 측정 성공과 별도. 기존 승인 절차와 운영 측 설정 필요, 이번 작업에서는 변경하지 않음 |
| GitHub push 거절 | 인증·저장소 주소·원격 커밋을 확인하고 중단. --force 사용하지 않음 |

## 2분 시연 순서

1. 실행 명령과 /daily 주소를 보여 줍니다.
2. 조회 전 상태에서 Tab·Enter로 ‘다시 조회’를 누르고 대기 표시를 보여 줍니다.
3. CPU %·메모리 GiB·디스크 GiB·측정 시각이 실제 값임을 설명합니다.
4. 다시 직접 조회해 CPU 추이와 이전 값 대비 %p 차이를 보여 줍니다.
5. Windows 읽기 제한을 ‘확인 불가’로 보여 주고 공격 탐지 건수가 아님을 설명합니다.
6. SDP 미연결, 외부 권한·실제 AI·보안 집행 미검증을 구분하고 기존 보안 Agent 링크를 보여 줍니다.
