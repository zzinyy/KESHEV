# 17단계 검증 기록

2026-10-22 확인. 학생 코드와 실제 연결 성취를 구분한다.

## 구현과 요청 경로

- 학생 표시: student/extension.mjs의 renderAiConnection과 renderExplanation.
- 제공 화면: public/app.js의 사건 설명 요청은 /api/ai/explain으로 전달된다.
- 제공 서버: src/server.mjs → src/ai/service.mjs → vendor/clco-http.mjs의 연결은 원문에 포함된다. 제공 파일은 수정하지 않았다.
- renderExplanation은 explanation.status가 ok인 현재 사건 응답에만 data-student-explanation-event를 붙인다. 오류·취소·대기에는 성공 표식을 붙이지 않는다.
- 연결 점검의 모델 목록 응답은 사건 설명 모델 호출 성공으로 기록하지 않는다.

## 확인 결과와 한계

- 모의 DOM: 시험/verified 점검 표시, 오류 분류, 민감값 제외, 수동 복구, 초기화, 사건 설명 성공·실패 표시를 확인했다.
- 제출 묶음에서 server.mjs와 clco-http.mjs의 전체 내용 및 Git 원문 일치를 확인했다.
- 실제 PC 브라우저 http://127.0.0.1:5189/는 연결 없음과 ENGINE_NOT_CONNECTED에 해당하는 연결 어댑터 안내를 표시했다. 학생 AI 표시는 구현 대기인 이전 파일이다.
- 실제 계정의 ai.explain 권한 승인과 생성 모델 응답 수용은 미확인이다. 성공 기록을 만들지 않았다.

## 사용자가 확인할 순서

1. 최신 학생 파일을 실제 실행 프로젝트에 반영한다.
2. 제공된 계정 연결과 AI 앱 승인 절차에서 계정·확인 번호·승인 범위를 확인한다. 운영자 권한이 준비되지 않았으면 담당자에게 문의한다.
3. AI 연결 점검을 수행한 뒤 보안 기록에서 본인 사건을 선택해 설명을 요청한다.
4. 해당 사건 ID의 실제 설명 응답이 표시되는지 확인한다. 실패는 오류 코드·안전한 메시지로 기록하며 실제 성공으로 바꾸지 않는다.

이 문서는 실제 모델 호출 완료를 증명하지 않는다. 서버 권한이나 판정 설정을 변경하지 않는다.
